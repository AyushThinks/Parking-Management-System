# Suggested 30-Commit Learning Plan

Use this plan when you are developing the project yourself or extending this starter. Each commit should contain a logical, tested change. The starter repository already has an initial history; this list is a learning roadmap for additional commits, not a substitute for understanding the changes.

1. Add project README and scope.
2. Add package entry point.
3. Add central configuration.
4. Add SQLite connection helper.
5. Add schema and indexes.
6. Add registration validation.
7. Add settings validation.
8. Add service-layer settings methods.
9. Add dashboard metrics query.
10. Add automatic slot allocation.
11. Add duplicate active-vehicle prevention.
12. Add vehicle exit and billing.
13. Add searchable record listing.
14. Add safe delete rules.
15. Add CSV export.
16. Add audit logging.
17. Add dashboard UI.
18. Add vehicle entry form.
19. Add records table and filters.
20. Add exit confirmation and receipt.
21. Add settings and audit view.
22. Add service tests for slot allocation.
23. Add duplicate-entry regression test.
24. Add full-capacity regression test.
25. Add settings and deletion tests.
26. Document SRS and acceptance criteria.
27. Document architecture and SIPOC.
28. Add FMEA and CTQ analysis.
29. Add defect checksheet and PDCA log.
30. Add SQC chart generation and viva notes.

For submission, your actual commit history should reflect changes you made, and you should be able to explain each commit in viva.
